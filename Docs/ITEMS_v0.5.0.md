## 1. 设计理念

### 数值平衡原则

- **基准物品**：原版"矿泉水"(typeID 1181)——能量 0 / 水分 40 / 价值 80
- 饮品水分值基准：普通饮品 40-50，高级饮品 50-70，顶级饮品 50-60（但附带强力 Buff）
- 食物能量基准：简餐 25-45，正餐 45-70
- 生存食物特点：高能量、低/负水分、长保质期概念（通过高 `maxDurability` 体现）
- 稀有度影响价值倍率：White ×1.0 / Green ×1.5 / Blue ×2.5 / Purple ×4.0

### 命名规范

- Identifier：全小写下划线分隔（`coffee_black`、`fish_sausage`）
- I18n Key：首字母大写的 PascalCase 或原始名（`CoffeeBlack`、`FishSausage`）
- 描述 Key：名称 Key + `_Desc`

### 使用效果类型

| UsageBehavior | 用途 |
|---|---|
| `FoodData` | 基础食物/饮水效果（能量 + 水分） |
| `HealData` | 直接治疗 |
| `AddBuffData` | 附加 Buff（带概率） |
| `RemoveBuffData` | 移除负面 Buff（带概率） |

## 6. 鱼类加工链

### 加工流程

```
任意原版鱼类（鲑鱼/鲈鱼/鲤鱼等）
  │
  ├──→ [原版工作台] 切割 → 鱼片(30028)
  │                              │
  │                              ├──→ 直接生吃（日料，低风险）
  │                              │
  │                              └──→ [原版工作台] 打浆 → 鱼糜(30029)
  │                                                          │
  │                                                          └──→ [原版工作台]
  │                                                              鱼肉香肠(30064)
  │
  └──→ [原版工作台] 直接烹饪（利用游戏原有烹饪系统）
```

### 数值设计理念

- 鱼类加工的每一步都提高物品的价值和安全性
- 生鱼片 → 低概率风险但保留了原始风味
- 鱼糜 → 去除了直接食用的风险，但本身价值不高
- 鱼肉香肠 → 最终产品，高价值、高能量、完全安全

### 原版鱼类兼容列表（待验证）

需要在 Phase 0 研究中收集游戏内所有鱼类物品的 typeID。预期兼容：
- 淡水鱼：鲤鱼、鲈鱼、鳟鱼等
- 海水鱼：鲑鱼、鳕鱼等
- 任何带有 `Fish` 标签的物品理论上都可以加工
